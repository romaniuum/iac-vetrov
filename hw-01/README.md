# ДЗ 1. Стенд для показов продукта

Стенд поднимается одной командой перед показом и сносится одной командой после.
Между показами в облаке ничего не остаётся и ничего не списывается.

## Из чего состоит

| Ресурс | Имя | Где |
|---|---|---|
| Сеть | `vetrov-09-net` | — |
| Подсеть A | `vetrov-09-subnet-a` | `ru-central1-d`, `10.19.1.0/24` |
| Подсеть B | `vetrov-09-subnet-b` | `ru-central1-a`, `10.19.2.0/24` |
| NAT-шлюз и таблица маршрутизации | `vetrov-09-nat`, `vetrov-09-rt` | таблица привязана к подсети A |
| Веб-серверы | `vetrov-09-web-1`, `vetrov-09-web-2`, … | по очереди в зонах A и B, nginx на порту `8027` |
| Сервер приложения | `vetrov-09-app` | зона A, **без публичного адреса** |
| Целевая группа и балансировщик | `vetrov-09-tg`, `vetrov-09-lb` | принимает на `80`, отдаёт на `8027` |

Машины настраиваются сами через `cloud-init.tpl.yaml`. Страница отвечает строкой вида
`cloudlab on vetrov-09-web-1`. Сервер приложения выходит в интернет (за пакетами)
через NAT-шлюз, а снаружи к нему попасть нельзя.

## Что нужно

- bash, `yc` (профиль с каталогом по умолчанию), `jq`, `envsubst` (пакет `gettext-base`), `curl`, `ssh`;
- публичный ключ `~/.ssh/id_ed25519.pub` (другой путь можно задать через `SSH_PUBKEY`).

## Как пользоваться

```bash
cd hw-01
./create.sh      # поднять; ждёт, пока check.sh пройдёт, печатает адрес
./check.sh       # проверить; код 0 — всё в порядке, 1 — нет
./destroy.sh     # снести всё своё
```

`create.sh` можно запускать повторно на поднятом стенде: существующее он пропускает,
остановленные облаком машины запускает, недостающие веб-серверы создаёт и добавляет
в целевую группу.

## Параметры

Все три сценария принимают одни и те же параметры.
Приоритет: **аргумент > переменная окружения > умолчание**.

| Аргумент | Переменная | Умолчание |
|---|---|---|
| `--prefix` | `PREFIX` | `vetrov-09` |
| `--zone-a` | `ZONE_A` | `ru-central1-d` |
| `--zone-b` | `ZONE_B` | `ru-central1-a` |
| `--cidr-a` | `CIDR_A` | `10.19.1.0/24` |
| `--cidr-b` | `CIDR_B` | `10.19.2.0/24` |
| `--port` | `APP_PORT` | `8027` |
| `--word` | `WORD` | `cloudlab` |
| `--web-count` | `WEB_COUNT` | `2` |
| `--env` | `ENV_NAME` | `lab` (метка `env`) |

```bash
./create.sh --web-count 3
WEB_COUNT=3 ./create.sh
./create.sh --print-params   # показать итоговые значения и откуда они взялись, ничего не создавая
./create.sh --help
```

Префикс, заданный при создании, нужно передать и в `check.sh`, и в `destroy.sh`.

## Что проверяет check.sh

1. Балансировщик отвечает кодом 200.
2. За 20 запросов ответила больше чем одна машина.
3. С веб-сервера (по ssh) сервер приложения отвечает по внутреннему адресу.
4. У сервера приложения нет публичного адреса.

## Если check.sh вернул 1

| Строка с ✗ | Что смотреть |
|---|---|
| балансировщика нет | стенд не поднят или снесён: `./create.sh` |
| балансировщик отвечает не 200 | `yc load-balancer network-load-balancer target-states --name vetrov-09-lb --target-group-id <id>`: все цели UNHEALTHY? значит nginx не поднялся, см. ниже |
| ответила только одна машина | вторая UNHEALTHY: зайти на неё, `sudo systemctl status nginx`, `sudo cloud-init status --long` |
| сервер приложения недоступен | нет выхода в интернет при первой загрузке: у подсети A должна быть таблица `vetrov-09-rt`. Затем `./destroy.sh && ./create.sh` — cloud-init работает только при первой загрузке |
| не удалось зайти по ssh | ключ не тот, что в `SSH_PUBKEY`, или веб-серверы остановлены: повторный `./create.sh` их запустит |

Машины прерываемые: облако может остановить их в любой момент и точно остановит через сутки.
Перед показом достаточно запустить `./create.sh` ещё раз.

## Уборка

`destroy.sh` не хранит список созданного, а спрашивает облако: всё с меткой `owner=<префикс>`
или с именем на `<префикс>-`. Удаляет в порядке балансировщик → целевая группа → машины →
диски → отвязка таблицы от подсети → таблица → шлюз → подсети → сеть, в конце проверяет,
что своего не осталось. Статические адреса без имени он не видит: `yc vpc address list`
стоит посмотреть самому.
